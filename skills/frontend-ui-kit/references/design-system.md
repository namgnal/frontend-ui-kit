# 视觉与体验取舍

## 先看产品再选风格

已有产品先找现有 tokens、基础组件、字体、栅格与当前的主要流程。可以通过间距、对齐、字号层级、文案和反馈的小幅修正显著改善体验，不需要先换框架、组件库或品牌。

新设计用一句话说清页面的核心任务，并说明视觉重点如何支持它。例如分析工作台需要便于扫读的密度与对齐；思考空间需要适宜行宽与安静的输入区域；品牌页面可以给一处主视觉更多表达空间。不要把三者都做成同一种卡片网格。

## 优雅

- 排版先区分标题、正文、辅助信息和可操作项。字号差别、字重与留白应共同表达优先级，避免所有信息都加粗。
- 中文正文注意行距与中英文混排，长文本用可读的行宽。文字不以颜色过浅换取“高级感”。
- 用对齐和空间组织信息。只在分组确实需要时添加边框、背景或阴影；组件圆角可有亲缘关系，不必统一成巨大胶囊。
- 保留真实内容的长标题、空状态和错误样本，避免只有短占位文字时才好看。

## 流畅

- 响应动作先于装饰动画。异步行为显示忙碌状态、防重复提交，失败时保留输入。
- 微反馈可从 120–180ms、区域过渡可从 180–260ms 试起，按实际内容调整；这些是本包建议值，不是 Claude 的官方参数。
- 优先动画 transform/opacity。高度变化只在语义明确且真实测量平稳时做，不用 `transition: all`。本包原生折叠的内容直接展开，只有箭头旋转。
- 流式内容不要每个 token 都平滑滚动；用户回看历史时停止自动跟随，提供回到最新的明确入口。
- 尊重 `prefers-reduced-motion`，保留文字反馈。不要让低性能设备、键盘用户或不喜欢动态效果的人付出代价。

## 舒适

- 常用触控目标优先接近 44px；密集工作台可按空间约束设计，但不能只剩难点中的小图标。
- 焦点、悬停、按下、禁用、加载与错误有清晰且一致的表达。状态文字不能完全依赖颜色或 spinner。
- 错误告诉用户发生了什么及下一步。成功反馈不遮挡持续操作，不伪造网络、保存或上传成功。
- 多语言和不同屏幕下保留操作标签，重要信息不应随容器变窄无声消失。

## 样式接入

新 React 示例用一个 `.fui-root` 容器加载 `tokens.css`、`components.css`。深色通过 `data-fui-theme="dark"` 显式选择；默认不读取或修改全站主题。`data-fui-palette="ink"` 提供另一种示例强调色，不代表品牌方案。

旧项目优先保留现有主题，让这个局部容器的 `--fui-text`、`--fui-bg`、`--fui-surface`、`--fui-accent` 等映射到项目已有的语义变量。若目标项目已有合适按钮/输入/弹窗，修复或组合它们，避免制造平行组件体系。

样式只使用 `fui-*` 类。不得整包引入原仓库全局字体覆盖、Tailwind 配置或 Electron 入口。不要直接把整套 CSS 塞到已有原子化样式配置里。

可运行 `node scripts/check-tokens.mjs` 检查包内变量引用；这只能证明变量有定义，不能证明对比度、浏览器兼容性或审美质量。
