# 验收：行为、视觉与实际限制

根据改动选择下列相关检查。先运行项目已有必要检查，再补实际风险所需的浏览器路径；小样式修改不必启动完整套件。

## 行为

- 主流程真实可操作；加载状态不会重复提交；失败保留用户输入；发送中编辑的新草稿不会被上一次请求完成时清除。
- 中文输入合成时的 Enter 不发送，普通 Enter 发送，Shift+Enter 换行。本包自动测试模拟 composition 事件，不能代替真实系统输入法的手工验证。
- 键盘路径可达并显示焦点；分段选项首尾循环并跳过禁用项；附件打开/移除互不误触；折叠后子控件不进入 Tab。
- 复制的空白内容保持原样；写入成功前不显示成功，拒绝权限后有恢复提示。
- 流式增长在底部跟随，滚离底部后不抢位置；内容变高或窗口变化后保持约定行为。

## 视觉与舒适度

- 看桌面与约 360px 窄屏，必要时检查 200% 缩放和长文本。页面整体无水平溢出，局部代码区域可横向滚动。
- 深浅主题中正文、辅助信息、焦点、边界均可辨识；自动对比度工具只是基础检查。
- 检查减少动态效果设置。动画停止后仍能理解忙碌与完成状态；没有隐形但挡住操作的层。
- 信息层次能否支持用户下一步；留白是否服务阅读；交互反馈是否精确；动效是否制造等待或眩晕。

## 证据与交付

有浏览器能力时在真实构建上完成操作并截图。记录 viewport、浏览器、版本、通过/失败项和未测范围。无浏览器时说明只做了静态或单元检查，不声称视觉验收完成。

用户感到舒适满意需要真实使用反馈。自动测试可验证功能与基础可访问性，截图可发现布局问题，均不能单独证明用户满意度。

本包自带项目工作台的测试用于回归配方；复制到目标项目后仍须检查其集成，因为全局 CSS、路由、状态和真实服务可能改变行为。
