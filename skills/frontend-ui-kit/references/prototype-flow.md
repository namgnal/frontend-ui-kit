# 原型与设计迭代

本参考提炼自 open-claude-design 的 frontend-design、interactive-prototype、wireframe、save-as-standalone-html 工作方式，已重写为宿主无关流程。来源与 Apache-2.0 文本见 ../licenses/。

## 选择合适的交付深度

讨论信息结构时用低保真布局即可；对视觉和交互做判断时做可运行页面；真实产品改动直接接入其构建、路由和数据层。不把讨论稿假装成生产实现。

用产品真实的主流程贯穿设计。按钮应有明确去向，表单有提交与失败反馈，筛选确实改变显示内容。还没接入后端的动作要如实标明演示，不用成功提示掩盖无操作。

## 工作节奏

1. 从需求和现有页面建立一个简短、具体的方向：内容优先级、空间密度、字级、品牌表达与一处关键交互。
2. 尽早展示一个有代表性的页面或状态，避免等所有页面完成才发现方向偏离。
3. 优化同一页面的真实使用细节：输入、切换、长内容、空状态、等待与恢复。
4. 在已有环境预览、操作、查看窄屏和截图，根据发现修正。完成用户要求的范围，非必要不新增流程。

已有 frontend-design 等技能可以提供视觉方向；不要机械叠加两套完整流程或重复提问。本包侧重把方向落实为可用组件与可验证行为。

## 技术选择

优先使用目标项目的技术栈。React 示例可复用到 React 客户端；Vue/Svelte/原生项目只借用语义和 CSS 原则，重新实现交互，不直接复制 TSX。

`assets/prototypes/static-reference.html` 是无需构建的 HTML/CSS 布局参考，使用相邻主题文件，不依赖 CDN；它不是单文件打包器，也不包含 React 的异步与滚动能力。

若用户需要可分享的独立 HTML，明确资源是否已经内联、是否仍有网络字体/图片/JS 依赖，并验证离线打开。不要把带相邻 JSX 文件或在线 CDN 的页面称为完全独立文件。需要多页、复杂状态时沿用项目打包器，不用正则拼接多个模块。

可选的受控参数面板见 [optional-tweaks.md](optional-tweaks.md)，仅在用户需要时接入。普通原型流程不依赖它。本包不提供代码注入、iframe 热替换或任意 DOM 节点回写。
