# Frontend UI Kit

帮助用户把产品做得优雅、流畅、舒适。优雅来自清晰的层次与一致的细节；流畅来自及时反馈、稳定布局和不中断的操作；舒适来自可读性、可控性及失败后仍能继续的体验。这是设计与实施工具包，组件只是可选素材，不是必须套用的视觉模板。

## 根据任务推进

- **优化现有产品**：先看用户指出的页面、实际流程、现有组件和设计变量。有运行环境时先打开页面，找出最影响理解或操作的具体问题。保留合适的品牌语言与技术栈；修改需要用可检查的前后效果说明。小修直接完成，大幅改版先展示方向。
- **新设计**：围绕产品用途、主要用户任务和真实内容确定布局、字体角色、密度与视觉重点。缺失信息只有在会改变结果时才询问。样例里的品牌、配色与文案不是新项目的默认答案。
- **局部交互**：定位输入、反馈、滚动、焦点或状态问题，按需使用组件配方，不扩展成整站重构。

## 取用资源

只读取当前工作需要的内容：

- 视觉层次、色彩、密度、动效与旧项目接入：[design-system.md](references/design-system.md)。
- 选择或接入按钮、分段选择、附件、状态、代码块、消息、输入框、折叠区域，以及流式滚动：[component-recipes.md](references/component-recipes.md)。代码在 `assets/react/`，React 是可选技术栈；不为了使用配方迁移现有项目。
- 新页面原型、交互范围与静态 HTML 路线：[prototype-flow.md](references/prototype-flow.md)。
- 浏览器验收、失败状态和体验检查：[verification.md](references/verification.md)。根据改动风险选择相关项。
- 用户需要亲手比较参数或明确要求调节面板时，才读取 [optional-tweaks.md](references/optional-tweaks.md)。日常仍通过一句话完成优化，不要求选参数、开面板或增加确认步骤；不默认把面板加入产品。

`assets/themes/tokens.css` 是独立示例主题，`assets/react/components.css` 是配方样式。现有项目优先把 `--fui-*` 语义映射到它自己的变量，只复制需要的组件并保留来源声明。完整来源、版本和许可证在 `sources.lock.json` 与 `licenses/`。

## 实施与完成

先让主流程可用，再打磨视觉与运动细节。用真实回调处理动作；异步操作提供明确的等待、成功或恢复路径。动效用来解释状态变化，不用不断移动的装饰证明“丝滑”。尊重减少动态效果设置，不用动画阻塞操作或抢走阅读位置。

使用宿主已有的构建与浏览器工具，不假设存在 `done`、`write_file` 或某个专属预览服务。本包不包含模型服务、密钥管理、通用可视化源码回写或自动部署。

交付时说明改了什么、用户体验为何改善、实际验证了什么及剩余限制。可预览时提供真实预览或截图。不要把静态检查称为浏览器验证，也不要把美观等同于用户满意度已经被证明。
